# System design интервью: подход и типовые задачи

> [!NOTE] Тема в работе
> Статьи по этой теме пока нет. Вот вопросы, на которые она ответит.

* Как проходить system design интервью: уточнение ФТ и НФТ, оценка нагрузки, API, high-level схема, углубление, узкие места и отказы
* HLD отвечает на вопрос «что и как на уровне системы», LLD — «как именно на уровне кода и протоколов»
* Оценка нагрузки «на салфетке»: DAU → RPS, пиковый коэффициент, соотношение чтения и записи, объём хранилища и трафик
* Спроектировать сокращатель ссылок (URL shortener): генерация коротких ключей, хранение, кэш, редирект 301 или 302, аналитика переходов
* Спроектировать rate limiter как отдельный компонент: требования, алгоритм, хранилище счётчиков, поведение при отказе Redis
* Спроектировать систему уведомлений (email, SMS, push): очередь, ретраи, дедупликация, приоритеты, шаблоны, отписки
* Спроектировать чат или мессенджер: постоянные соединения, доставка и порядок сообщений, хранение истории, статус онлайн
* Спроектировать асинхронную обработку тяжёлых HTTP-запросов: 202 Accepted, идентификатор задачи, очередь, опрос статуса или callback
* Загрузка файлов напрямую в объектное хранилище по presigned URL вместо проксирования через сервис
* Генерация уникальных ID в распределённой системе: UUID, Snowflake, последовательности с шагом — что выбрать
