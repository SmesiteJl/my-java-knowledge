# Валидация входных данных: JSR-303, свои валидаторы, ошибки валидации

> [!NOTE] Тема в работе
> Статьи по этой теме пока нет. Вот вопросы, на которые она ответит.

* Стандартные аннотации Bean Validation: @NotNull, @Size, @Min, @Max, @Email, @Pattern, @Positive
* Включение валидации в контроллере: @Valid над DTO
* Своя аннотация-ограничение: @Target, @Retention, @Constraint(validatedBy), параметры message, groups, payload
* Реализация ConstraintValidator.isValid и роль ConstraintValidatorContext
* Что происходит, если валидация не пройдена (ConstraintViolationException)
* BindingResult и RedirectAttributes рядом с @Valid @ModelAttribute; сообщения в @NotBlank, @Size, @FutureOrPresent
* Аннотация-ограничение на уровне класса (@Target(TYPE)): должен быть заполнен либо VIN, либо госномер
* ConstraintValidator<SearchValidation, SearchRequest> и метод isValid для проверки нескольких полей
* Ошибка на конкретное поле: buildConstraintViolationWithTemplate, addPropertyNode, addConstraintViolation, disableDefaultConstraintViolation
* @ExceptionHandler(MethodArgumentNotValidException): ответ 400 со списком ошибок полей (поле, код, сообщение)
