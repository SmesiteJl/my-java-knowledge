# Теорема Бёма–Якопини

Супер нишевая тема с первого курса, которую знают только автор и научные сотрудники.

Для остальных она звучит так: *любая программа представима через последовательность, ветвление и цикл*.

Раньше ветвления и циклы в программах собирались вручную, из переходов. Логика строилась от «контрольных точек» — меток: ставишь контрольную точку, даёшь ей имя и потом через оператор `goto` прыгаешь на эту точку — назад или вперёд. Именно так реализовывались цикл и ветвление. Бём и Якопини в 1966 году доказали, что без произвольных прыжков можно обойтись: любую такую программу можно переписать на трёх конструкциях.

## Как это выглядело на `goto`

Сумма чисел от 1 до `n` на метках. Пример на C — в нём `goto` есть до сих пор:

```c
int i = 1, sum = 0;
loop:
    if (i > n) goto end;  // ветвление — условный прыжок вперёд
    sum += i;
    i++;
    goto loop;            // цикл — прыжок назад
end:
    printf("%d\n", sum);  // 15 при n = 5
```

То же самое на трёх конструкциях:

```java
int i = 1, sum = 0;
while (i <= n) {
    sum += i;
    i++;
}
System.out.println(sum); // 15 при n = 5
```

Здесь переписать легко: прыжки ложатся ровно на `while`. А вот если `goto` скачут из середины одного цикла в середину другого, на глаз уже не перепишешь — и тут нужна сама теорема.

## Научная формулировка

Оригинальная статья — Коррадо Бём и Джузеппе Якопини, [«Flow Diagrams, Turing Machines and Languages with Only Two Formation Rules»](https://doi.org/10.1145/355592.365646), журнал Communications of the ACM, 1966. В [современной формулировке](https://en.wikipedia.org/wiki/Structured_program_theorem) теорема звучит так: блок-схемы, собранные только из трёх управляющих конструкций, могут вычислить любую вычислимую функцию:

* **последовательность** — выполнить один фрагмент, затем другой;
* **ветвление** — выполнить один из двух фрагментов в зависимости от значения логического выражения;
* **цикл** — повторять фрагмент, пока логическое выражение истинно.

«Любую вычислимую функцию» — то есть всё, что вообще можно посчитать, например на машине Тьюринга.

Подвох — в мелком шрифте: структурированной программе может понадобиться **дополнительная переменная**. В ней хранится то, что исходная программа «помнила» местом, где она сейчас находится. В оригинальном доказательстве это одна лишняя целая переменная.

## Любой `goto` можно заменить на `if-else` и `while`

Вот как это работает механически. Нумеруем куски программы между метками, заводим переменную `pc` — «на какую метку мы бы сейчас прыгнули» — и крутим один `while`, который по `pc` выбирает, какой кусок выполнить:

```java
int pc = 1;          // номер метки, на которую мы бы прыгнули через goto; 0 — программа закончилась
int i = 1, sum = 0;
while (pc != 0) {
    if (pc == 1) {            // loop: if (i > n) goto end;
        pc = (i > n) ? 3 : 2;
    } else if (pc == 2) {     // sum += i; i++; goto loop;
        sum += i;
        i++;
        pc = 1;
    } else {                  // end: печатаем и выходим
        System.out.println(sum); // 15 при n = 5
        pc = 0;
    }
}
```

Каждый `goto` превратился в присваивание `pc`, каждая метка — в ветку `if-else`, а вся программа — в один цикл. Так можно переписать что угодно. Отсюда популярная «народная» версия теоремы: любая блок-схема эквивалентна программе с одним `while`, если разрешить дополнительные переменные.

Понятно, что читать такое никто не захочет. **Теорема доказывает, что `goto` не обязателен, но красивую программу за нас не строит.**

## Что было дальше

Кстати!

Сама статья Бёма и Якопини была про блок-схемы и машины Тьюринга, а не про то, как писать код. Войну с `goto` начал Эдсгер Дейкстра в 1968 году письмом в тот же журнал — [«Go To Statement Considered Harmful»](https://doi.org/10.1145/362929.362947). Причём [такой заголовок](https://en.wikipedia.org/wiki/Considered_harmful) придумал не он, а редактор журнала Никлаус Вирт: у Дейкстры письмо называлось «A Case Against the Goto Statement». С тех пор «… considered harmful» — устойчивый шаблон для заголовков критических статей.

Что из этого осталось в Java:

* `goto` — **зарезервированное слово, которое ничего не делает**. Как говорит [спецификация языка](https://docs.oracle.com/javase/specs/jls/se25/html/jls-3.html#jls-3.9):

    > Ключевые слова `const` и `goto` зарезервированы, хотя сейчас не используются. Это может помочь компилятору Java выдавать более понятные сообщения об ошибках, если эти ключевые слова C++ по ошибке встретятся в программе.

    Назвать так переменную тоже нельзя:

    ```java
    int goto = 1; // не скомпилируется
    ```

* `break` и `continue` с меткой — единственный «прыжок» в Java, и только наружу из вложенных циклов:

    ```java
    outer:
    for (int a = 0; a < 3; a++) {
        for (int b = 0; b < 3; b++) {
            if (a * b == 2) break outer; // выходим сразу из обоих циклов
            System.out.print(a + "" + b + " ");
        }
    }
    // 00 01 02 10 11
    ```

    У таких выходов тоже есть теория: в 1973 году Рао Косараджу доказал, что без дополнительных переменных можно обойтись, если разрешить выход сразу из нескольких вложенных циклов.

## Что имеем по итогу

Любую программу можно собрать из трёх кирпичей — последовательности, ветвления и цикла, — иногда ценой дополнительных переменных. На этом стоит структурное программирование: в Java нет `goto`, а всё управление — это `if`, `switch`, циклы, `break` и `continue`.
