# Вычислительная сложность и O-нотация

> [!NOTE] Тема в работе
> Статьи по этой теме пока нет. Вот вопросы, на которые она ответит.

* Критерии качества кода: время работы, используемая память, красота (структурированность, краткость, понятность); как их оценивать
* Вычислительная сложность: определение; сложность по времени T(n) и по памяти S(n) — важен порядок роста, а не точная формула
* Оценка времени работы: число элементарных операций и соответствие реальному времени (10^8 операций ≈ 1 с)
* Оценка используемой памяти: число элементов и размеры типов (char, int, long, double, указатель)
* Асимптотическое время работы, O-символика: формальное определение O-большого — f(n) = O(g(n)), если |f(n)| ≤ C·g(n), операции с ним; подход к измерению сложности
* Сложность в лучшем, худшем и среднем случае; почему важна оценка сверху
* Виды сложности: константная, логарифмическая, линейная, полиномиальная, экспоненциальная
* Примеры: k вложенных циклов — O(n^k), максимум массива — O(n), рекурсивный Фибоначчи — O(2^n)
* NP-трудные и NP-полные задачи
* Амортизированная сложность: почему add в ArrayList и put в HashMap с расширением стоят O(1) амортизированно
* Оценка сложности своего решения на лайвкодинге с учётом методов стандартной библиотеки: contains у ArrayList против HashSet, склейка строк в цикле, substring, sort
