# REST: принципы и практические правила

> [!NOTE] Тема в работе
> Статьи по этой теме пока нет. Вот вопросы, на которые она ответит.

* Шесть ограничений REST: client-server, stateless, cacheable, uniform interface, layered system, code on demand
* Чем REST отличается от RESTful API; модель зрелости Ричардсона и HATEOAS — зачем он нужен и почему его почти не используют
* REST на практике: HTTP-методы, URI как ресурс, JSON или XML; ресурсы и методы — GET /user, GET /user/42, POST /user, PUT и PATCH /user/42, DELETE /user/42
* Как именовать эндпоинты: ресурсы-существительные во множественном числе, вложенные ресурсы, почему не глаголы в URL и как выразить действие (POST /orders/{id}/cancel)
* Пример REST-ответа в JSON для DTO: формат полезной нагрузки data (элементы и пагинация), status, notices — дополнительная служебная информация в ответе
* Версионирование REST API: в URI, в заголовке или через media type; какие изменения ломают клиентов и как сохранить обратную совместимость
