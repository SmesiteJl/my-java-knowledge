# Тестирование конкурентного доступа

> [!NOTE] Тема в работе
> Статьи по этой теме пока нет. Вот вопросы, на которые она ответит.

* Сценарии конкуренции: два пациента на один слот, двойная отправка, повтор после обрыва сети, две ноды почти одновременно
* Ожидаемый результат: создаётся одна запись, второй запрос получает 409 или прежний результат, БД консистентна
* Почему нужны реальные параллельные сценарии с нагрузочным инструментом, а не только API-тесты
* Конкурентный доступ к одному слоту: блокировка выдаётся первому пациенту
* Второй получает «slot already taken» и ответ 409
* Почему тест с одним клиентом не воспроизводит гонку
* CONC-01 «последняя единица», CONC-02 «один ключ 50 раз», CONC-03 «два назначения одновременно»
* SQL-проверки инвариантов после теста: резерв не больше остатка, резерв равен сумме позиций, одно активное назначение
