# Böhm–Jacopini Theorem

A super niche first-year topic that only the author and a few researchers know.

For the rest of us, it goes like this: *any program can be expressed using sequence, branching, and loops*.

Early programs built branches and loops by hand out of jumps. The logic revolved around checkpoints called labels: mark a spot, give it a name, and use `goto` to jump there, backward or forward. That's how loops and branches worked. In 1966, Böhm and Jacopini proved that arbitrary jumps aren't necessary: we can rewrite any such program using three constructs.

## What it looked like with `goto`

Let's add up the numbers from 1 to `n` using labels. The example is in C, which still has `goto`:

```c
int i = 1, sum = 0;
loop:
    if (i > n) goto end;  // branch: a conditional jump forward
    sum += i;
    i++;
    goto loop;            // loop: a jump backward
end:
    printf("%d\n", sum);  // 15 when n = 5
```

Here's the same thing using only those three kinds of constructs:

```java
int i = 1, sum = 0;
while (i <= n) {
    sum += i;
    i++;
}
System.out.println(sum); // 15 when n = 5
```

That one's easy to rewrite: the jumps map right onto a `while`. But once `goto` statements start jumping from the middle of one loop into the middle of another, we can't just eyeball a rewrite. That's where the theorem comes in.

## The formal statement

Corrado Böhm and Giuseppe Jacopini's original paper, [“Flow Diagrams, Turing Machines and Languages with Only Two Formation Rules”](https://doi.org/10.1145/355592.365646), appeared in *Communications of the ACM* in 1966. In its [modern formulation](https://en.wikipedia.org/wiki/Structured_program_theorem), the theorem says that flowcharts built from just three control-flow constructs can compute any computable function:

* **sequence** — run one piece of code, then another;
* **branching** — run one of two pieces of code depending on the value of a boolean expression;
* **looping** — repeat a piece of code while a boolean expression is true.

“Any computable function” means anything that can be computed at all, for example by a [Turing machine](https://ru.wikipedia.org/wiki/%D0%9C%D0%B0%D1%88%D0%B8%D0%BD%D0%B0_%D0%A2%D1%8C%D1%8E%D1%80%D0%B8%D0%BD%D0%B3%D0%B0) (Russian).

Here's the catch: the structured program may need an **extra variable**. It stores what the original program “remembered” just by being at a particular spot in the code. The original proof uses one extra integer variable.

## Replacing any `goto` with `if-else` and `while`

Here's the mechanical rewrite. We number the chunks of code between labels, introduce a variable `pc` to keep track of where we'd jump next, and run a single `while` loop that uses `pc` to pick which chunk to execute:

```java
int pc = 1;          // number of the label we'd jump to with goto; 0 means the program is done
int i = 1, sum = 0;
while (pc != 0) {
    if (pc == 1) {            // loop: if (i > n) goto end;
        pc = (i > n) ? 3 : 2;
    } else if (pc == 2) {     // sum += i; i++; goto loop;
        sum += i;
        i++;
        pc = 1;
    } else {                  // end: print the result and exit
        System.out.println(sum); // 15 when n = 5
        pc = 0;
    }
}
```

Every `goto` became an assignment to `pc`, each label became an `if-else` branch, and the whole program became one loop. We can rewrite anything this way. That gives us the popular “folk” version of the theorem: any flowchart is equivalent to a program with a single `while` loop if we allow extra variables.

Of course, nobody wants to read code like that. **The theorem proves we don't need `goto`; it doesn't write readable code for us.**

## What made it into Java

* `goto` is a **reserved word that doesn't do anything**. As the [language spec](https://docs.oracle.com/javase/specs/jls/se25/html/jls-3.html#jls-3.9) puts it:

    > The keywords `const` and `goto` are reserved, even though they are not currently used. This may allow a Java compiler to produce better error messages if these C++ keywords incorrectly appear in programs.

    We can't name a variable `goto` either:

    ```java
    int goto = 1; // won't compile
    ```

* Java doesn't let us jump to arbitrary labels. A [labeled `break`](https://docs.oracle.com/javase/specs/jls/se25/html/jls-14.html#jls-14.15) exits the labeled statement, which can be a loop or even a block. A [labeled `continue`](https://docs.oracle.com/javase/specs/jls/se25/html/jls-14.html#jls-14.16) skips the rest of the current iteration of the labeled loop:

    ```java
    outer:
    for (int a = 0; a < 3; a++) {
        for (int b = 0; b < 3; b++) {
            if (a * b == 2) break outer; // exit both loops at once
            System.out.print(a + "" + b + " ");
        }
    }
    // 00 01 02 10 11
    ```

    There's a result about these exits, too: in 1973, Rao Kosaraju proved that we can avoid extra variables if we're allowed to break out of multiple nested loops at once, at any depth.

## The takeaway

We can build any program out of three building blocks: sequence, branching, and loops, sometimes at the cost of extra variables. That's the basis of structured programming. Java doesn't have `goto`; for this kind of control flow, we use `if`, `switch`, loops, `break`, and `continue`.
